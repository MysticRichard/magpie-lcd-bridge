# 功能规格：跨项目 BLE 租约

## 1. 概述

本功能在 Magpie LCD Bridge 托盘控制器中增加仅限本机的 BLE 租约接口。墨笺 InkMemo 在扫描、校准或传输前申请租约；控制器暂停 LCD worker 并确认进程退出后批准。墨笺释放租约后，控制器恢复原显示状态。

目标是避免两个项目同时操作同一个 Windows 蓝牙适配器，而不是修改任一设备的 BLE 协议、固件或刷新间隔。

## 2. 用户场景与测试

### 用户故事 1 - 墨笺操作期间释放 LCD 蓝牙（P1）

作为同时使用 LCD 与墨笺的用户，我希望墨笺开始 BLE 操作时 LCD 自动暂停，结束后自动恢复，这样两个程序不再争用适配器。

**验收场景**

- **US1/AC1**：给定 LCD worker 正在运行，当墨笺成功申请租约时，控制器停止 worker，并在响应前完成进程退出等待。
- **US1/AC2**：给定墨笺持有租约，当墨笺调用释放时，如果申请前 worker 正在运行，控制器启动一个 worker。
- **US1/AC3**：给定申请前 worker 本来已停止，当墨笺释放租约时，控制器不得擅自启动 worker。
- **US1/AC4**：给定墨笺持有租约，LCD 托盘必须显示外部 BLE 占用状态，并拒绝用户同时启动或重启显示。

### 用户故事 2 - 异常退出自动回收（P1）

作为用户，我希望墨笺崩溃或漏掉释放时，LCD 最终自动恢复，而不是永久停摆。

**验收场景**

- **US2/AC1**：租约带有效期；墨笺按固定间隔发送心跳续期。
- **US2/AC2**：给定租约超时，当控制器巡检时，自动清除租约并按申请前状态恢复 worker。
- **US2/AC3**：无效 token、其他 owner 或已过期租约不得释放或续期当前租约。

### 用户故事 3 - 墨笺只在 BLE 操作期间申请（P1）

作为用户，我希望取数、渲染和普通预览不触发租约，只有真正使用蓝牙时才暂停 LCD。

**验收场景**

- **US3/AC1**：`preview` 与内容未变化的同步不申请租约。
- **US3/AC2**：扫描、校准、正常发送与缓存失败发送在整次 BLE 操作期间持有同一租约。
- **US3/AC3**：BLE 操作成功或失败后都必须释放租约。
- **US3/AC4**：控制器不存在时，墨笺记录协调不可用并保持现有独立运行能力。
- **US3/AC5**：控制器明确返回 `busy` 时，墨笺不得继续扫描或连接 BLE，并向用户显示蓝牙被占用。

### 边界与错误处理

- 外部租约期间 LCD 可能回到固件时钟模式，这是可接受的短暂代价。
- 租约只协调主动遵守协议的本机程序，不锁定 Windows 蓝牙驱动或其他未知程序。
- 命名管道损坏、控制器崩溃或旧 token 不得导致永久租约。
- 默认 60 秒刷新间隔与现有 UI 不得改变。

## 3. 功能需求

- **FR-001**：控制器 MUST 提供版本化、仅限本机的命名管道接口，至少支持 `status`、`acquire`、`heartbeat`、`release`。
- **FR-002**：`acquire` MUST 使用随机安装密钥认证，并返回 owner token 与有效期。
- **FR-003**：不同 owner 的有效租约 MUST 返回 `busy`，不得覆盖现有租约。
- **FR-004**：`acquire` MUST 记录 worker 申请前状态；运行中则停止，停止则保持停止。
- **FR-005**：`release` MUST 校验 token，并仅在申请前 worker 正在运行时恢复 worker。
- **FR-006**：控制器 MUST 在租约超时后自动回收，并执行与正常释放相同的恢复逻辑。
- **FR-007**：托盘 UI MUST 阻止用户绕过有效外部租约启动或重启 worker。
- **FR-008**：墨笺 MUST 在扫描与 `transfer_with_retries` 外层申请租约，覆盖全部连接重试。
- **FR-009**：墨笺 MUST 在固定间隔发送心跳，并在 `finally` 中释放租约。
- **FR-010**：墨笺在协调器不可用时 MUST 记录并可继续独立运行；在明确 `busy` 时 MUST 中止 BLE 操作。
- **FR-011**：协议、密钥路径、默认 TTL 和错误码 MUST 有文档且可测试。
- **FR-012**：本功能 MUST NOT 修改 BLE 图片协议、固件、刷新间隔或设备写入方式。

## 4. 关键实体

- **BLE Lease**：owner、token、开始时间、到期时间、申请前 worker 状态。
- **Lease Request**：版本、操作、owner、token、TTL。
- **Lease Response**：成功状态、租约状态、token、剩余时间、worker 状态。
- **Coordinator Key**：控制器启动时生成、保存在当前用户本地目录、仅用于命名管道认证的随机字节。

## 5. 成功标准

- **SC-001**：自动测试覆盖租约申请、冲突、心跳、释放、超时和错误 token。
- **SC-002**：自动测试覆盖墨笺获取失败、busy、心跳与 `finally` 释放。
- **SC-003**：本机命名管道端到端测试可在 3 秒内完成一次申请和释放。
- **SC-004**：连续 3 次墨笺校准期间 LCD 不再发生非计划 BLE 写入超时，并记录双方日志。
- **SC-005**：终止墨笺进程后，LCD 在 TTL 到期后自动恢复。
- **SC-006**：现有 LCD 与墨笺测试全部通过。

## 6. 假设与范围外

- Windows 当前用户运行两个应用；不提供跨用户或跨主机协调。
- 墨笺通过固定命名管道协议接入，不新增网络端口。
- 范围外：多 Bluetooth 适配器选择、驱动修改、HCI 抓包、Windows 服务、跨设备锁、自动修改其他 BLE 程序。
